# Dependencies

Creator Studio's skills use outside tools. **You, the agent, check for each one before the stage that needs it, and install what is missing** (with the user's OK where noted). Only the user can sign in to accounts, approve connectors and pay. Never substitute a different tool, model or route because something is missing.

## How to handle a missing dependency
1. **Check** with the command in the table. Run all the checks for the stages in this request, once, up front.
2. **Say what is missing and what you will run**, in one short message. Ask for the user's OK before anything that uses `sudo`, installs globally, or writes outside the project and `~/.claude/skills/`. Installing inside `~/.claude/skills/` for the Higgsfield skill is covered by the user's request to set up Creator Studio.
3. **Install** with the command for the user's system. Use only the sources named here.
4. **Verify** by re-running the check. Record anything installed in the production's `status.md` ("Dependencies: installed X on <date>").
5. If you cannot install (no network, no permission, no package manager), say exactly what is missing and the single next step for the user. Save that as the production's next action and carry on with whatever stages do not need it.

Never type passwords, tokens or payment details for the user, never create accounts, and never run an install script from a URL not named in this file.

## First-run environment check
On a first run, run the checks above for FFmpeg, libass, the Higgsfield skill, whisper.cpp and Rubber Band (only if narration timing or audio treatment is in scope) and the selected connectors or OpenRouter environment/tools, and report them to the user as a short ready / missing list. Offer to fix the missing ones that can be installed here, and say which ones need the user to sign in. Skip dependencies for stages the user will not use. Providers are optional and mixable per modality; check only the selected routes. If OpenRouter is selected, detect a missing `OPENROUTER_API_KEY` using the exit-status-only test above and give the export guidance from that row. Its public model lists need no key: offer to seed the first project from live choices via the `studio` setup flow and [the existing template/defaults merge](project-file.md#seeding-a-new-project), even with no project or defaults file yet. A missing key blocks generation, not discovery or seeding.
