# Speech render

Minimum inputs: selected render text (narration script or dialogue script/cast), project/production identity, resolved voice profile, route and authorized draft/final settings. Direction comes from `elevenlabs-voice-director`, with `ai-voiceover` where needed. The model ALWAYS comes from the project's resolved voice profile (`voices[].model`); resolve explicit production choices into that profile for their scope, respecting `models.voice.allowed` / `locked`. `models.voice.default` may guide setup, never silently replace a cast profile. If missing, obtain a choice before rendering; no code/provider default.

- **Takes:** the selected render text, voice, model and settings.
- **Makes:** speech files (one per chunk, split-map piece or line) in narration order, with the text hash and provider job ID.
- **Tool:** ElevenLabs through the installed connector or signed-in web app; OpenRouter through curl (route `openrouter`).
- **Save:** put the files in the production folder and add a line to `status.md`.

## Render directly
1. Read the `studio` skill → `references/models/elevenlabs.json` and `references/elevenlabs-tagging.md` (cited model/route rules). **Before sending tagged ElevenLabs text on either route**, check the selected upstream model's `tags_supported` (explicitly map an OpenRouter id to its direct id without changing the selected model). Unknown support is not permission to send tags. For false, strip direction tags or convert to punctuation/supported settings, preserving spoken words; list unexpressible direction. No SSML `<break>` on v3/v4; `<phoneme>` only on Flash v2. Check the actual connector/browser schema too; REST parameters do not prove MCP/web exposure.
   - Apply project `audio.chunking.target_chars` and `audio.max_chunk_chars` within the selected route/endpoint ceiling. Split at paragraphs/sentence breaks, never inside a tag or sentence; count final outgoing tags too. When the project sets `audio.chunking.split_at`, the pieces come from the split map instead ("Split-point rendering" below). Repository conservative targets are v3 ~2,700 (runbook), v4/v4 Turbo 4,000 ([inferred], untested repository choice). These are not hard limits: v3 5,000, v4 10,000; v4 Turbo 10,000 is verified only on OpenRouter, direct limit [unverified]. Text to Dialogue has its own 2,000 total across `inputs[].text`, each with a `voice_id`. An oversized sentence needs an explicit edit decision.
   - [inferred] Repeat the active emotion tag at each chunk start when it fits the opening sentence, not a one-off laugh/SFX. Before a paid render, confirm the director's tag QC is clean (`elevenlabs-voice-director` → 4a-7: no question-type tag on a statement, no tone change at a take or chunk seam); if it is missing, return the text to the director. Where supported, pass `previous_text` / `next_text` for continuity: direct TTS API fields, or OpenRouter `provider.options.elevenlabs` (~500 characters each way: previous suffix / next prefix). Omit unavailable MCP/web fields and record that limitation.
   - [measured-controlled] Tags that persist or time things are model-dependent (shared reference → **Measured v3 vs v4**): repeat a delivery tag (`[whisper]`, `[quietly]`, `[softly]`) per sentence/section where it must hold; after any v3/v4 switch loudness-check and level-match (v4 measured ~8 dB quieter with no tag); `[long pause]` is not a fixed duration (measured ~4.8 s on v3, ~1.8 s on v4), so for exact gaps use punctuation, separate chunks or silence in `audio-post-mix`. Re-run a few tagged lines on the actual voice/model before final renders. Refuse to render tagged text whose director header (`model`, `tag_profile`) is missing or differs from the resolved profile model; return it to `elevenlabs-voice-director` instead. See **Model switch / migration** below.
   - Never send `speed` to v4/v4 Turbo; OpenRouter rejects non-default speed. Never send `instructions` to ElevenLabs via OpenRouter; put ALL direction in `input` as tags/punctuation. Confirm any other setting against the selected route before sending.
   For OpenRouter use the section below; for direct MCP/web use the remaining steps.
2. Save the full outgoing text and its hash, with segment/beat spans and explicit order. Dialogue maps speaker + line index + chunk index for **every** chunk of a long line; never keep only its first chunk. An 80-character preview is not a render input.
3. For MCP, use the same exact text/voice/model/settings for `estimate_only: true` and the authorized render; set `generations_count: 1` unless multiple takes were requested. For web, use available signed-in browser tools, paste text, read it back in full, verify settings and cost before generating. Browser access is an environment dependency; report it if absent.
4. Preserve project test-first and listening gates and `studio`'s existing authorization/caps. For switches or mixed v3/v4 renders, follow `references/elevenlabs-tagging.md` → **Model changes and listening review** in `studio`; a model switch on an approved production requires the user’s listening gate again. Never record an approval on the user’s behalf. Submit once, poll job status; do not resend a slow call.
5. Persist every provider output promptly with `asset-persist` (flow URLs may expire in about two hours). Record voice/settings, text/hash, provider generation/job/result ID, take/version and review state. Record the actual render model for every take in both its `<file>.json` sidecar and `status.md`, using `studio` → `references/output-sidecar.md` and `references/production-handoff.md`; flag affected tagged takes for re-listening on a model change per the shared tagging reference.

## Split-point rendering (`audio.chunking.split_at`, opt-in)
Missing, `null` or `"section"`: chunking above, unchanged. `"sentence"` or `"phrase"`: the split map marks every piece boundary (rule: `elevenlabs-voice-director` → Step 6 "Split granularity"); this section is how those pieces are rendered. Not used in the sleep register.
- **One request per piece.** A piece is the text between two consecutive split-map entries (or the text start or end). Never merge two pieces into one request, and never split a piece further; a piece over `audio.max_chunk_chars` or the route ceiling needs an explicit edit decision, as an oversized sentence does.
- **Complete mapping.** For every piece record: piece index, the split-map ids on each side, sentence id(s) (`Pn.sK`), outgoing text and hash, provider request/generation id, and the continuity fields actually sent. The pieces and the split map must account for every script word once, in order, with none missing; check this before the join, which consumes the mapping (`audio-treatment` → "Split-map assembly").
- **Continuity across pieces.** Render in order and send neighbouring context on every piece:
  - Direct TTS API: `previous_text` / `next_text` ([verified] API fields, `studio` → `references/elevenlabs-tagging.md`), about 500 characters each way from the neighbouring pieces' plain text (tags stripped); and `previous_request_ids` from the preceding pieces' responses (at most 3, each at most 2 h old, as `elevenlabs-voice-director-sleep` → "Carry-over" describes).
  - OpenRouter: `previous_text` / `next_text` under `provider.options.elevenlabs`; no `previous_request_ids` (undocumented on that route).
  - MCP: `studio` → `references/models/elevenlabs.json` lists a `context` input in the live `creative_generate_speech` schema, but what it carries is not documented in this repo. Read the live schema; send only fields it names; otherwise record `continuity: not sent`. Never invent MCP or web fields.
  - [unverified] Request stitching (`previous_request_ids`) on v4 for this mode, and whether any of these fields keeps prosody continuous across sentence- or phrase-sized pieces. The only route evidence in this repo is sleep chunks of 800-3,500 characters, with the effect of each field not isolated. Record exactly what was sent per piece.
- **Listening test before first use.** Before the first episode of a project renders in this mode, run a one-paragraph A/B: the same paragraph as pieces (the project's `split_at`, with continuity, assembled per the split map) and as a single take, same voice, model, settings and seed. The user listens to both; record the verdict in `status.md`. It is a paid test, so it needs the usual authorization. Until the user passes it, do not render an episode in this mode; never record the verdict on the user's behalf.
- **More requests for the same characters.** Billing is per character, so credits stay about the same [inferred; whether context fields are billed is unverified], but an episode becomes one request per piece (with `"sentence"`, at least one per sentence) instead of a handful: more estimates, polls, persists and per-piece transcript audits. Persist each piece as it lands (flow URLs may expire in about two hours) and run local speech-to-text one at a time as below.

## Transcript audit
After every render, transcribe each chunk (`creative_transcribe_audio`, whisper.cpp or equivalent, installed per `studio` → `references/dependencies.md`; a local speech-to-text run goes one at a time, never beside a render: `studio` → `references/local-jobs.md`) and diff it against the chunk's plain script: no tag text spoken, no dropped, added or changed words, no unrequested stammers/groans (v4). Audit per chunk; a whole-file pass does not clear a chunk-level mismatch.
- **No user verdict step before the join.** A flagged mismatch triggers **one** automatic re-render of that chunk (same text after any director fix, same voice, model, settings and seed), within the approved budget cap (`spend.limit_credits` / the production's authorized amount). If that re-render would exceed the cap, do not render; mark the chunk instead.
- Re-audit the re-rendered chunk. If it passes, keep it and log both takes. If it is still flagged, keep the better take, continue to the join, and **mark it in the final report** (chunk, timestamp of the word in the program, script words vs heard words) for the user's listening gate. Never a second automatic re-render.
- Hand slurred or fused word sequences found here back to the director for its watchlist (`elevenlabs-voice-director-sleep` → 4e-1, when that register is in use).

## Model switch / migration (v3 <-> v4)
When a project's voice model moves v3 to v4 or back (or a production mixes them), what changes is delivery, level and timing, not just the model id. Evidence is one voice, one sentence ([measured-controlled]; measurements are not listening judgements; some results are one take), so every point below is a check to run, not a prediction to trust.
- **Never mutate automatically.** Do not edit an existing project's `project.json`, voice profile, `timing_doctrine`, loudness target or approved takes to "fit" a new model. A production override is recorded in `status.md` for its scope; a profile change is the user's decision. A project's `timing_doctrine` and loudness target are project-owned: apply them as written and flag mismatches, never rewrite them.
- **Text**: the director (`elevenlabs-voice-director`) regenerates the tagged text from the plain script with the new model's tag profile. Do not reuse the old tagged text. Quiet tags (`[whisper]`, `[quietly]`, `[softly]`) behave differently: v3 quieter and voiced, v4 mostly unvoiced/breathy, so a v3 sleep script moved to v4 must not keep them by default.
- **Checklist before any final**:
  1. Re-audition every tagged line, and every pause, on the new model (user listening gate runs again; never record an approval on the user's behalf).
  2. Pauses: `[long pause]` measured ~4.8 s (v3) vs ~1.8 s (v4); do not assume lengths carry over. Re-time per audition, or move exact gaps to chunk breaks and `audio-post-mix` silence.
  3. Loudness: re-measure each take (integrated LUFS, true peak) and re-normalize to the PROJECT target (e.g. -19 LUFS for a sleep podcast) via `audio-master`/`audio-post-mix`. Untagged v4 measured ~8 dB quieter than v3, and tagged results vary by tag; never rely on raw render level and never match models by ear alone.
  4. Transcript audit: transcribe each take (`creative_transcribe_audio` or equivalent) and diff against the plain script. No tag text spoken, no dropped or added words, no unrequested stammers/groans (v4).
  5. Record the actual render model per take in the `<file>.json` sidecar and `status.md`, with the tag profile used; flag takes whose recorded model differs from the resolved profile `pending_review`. Preserve old takes' model and review history.
- **New voice or project**: if the director's A/B audition (director 4f) has not been run on this voice, offer it before committing a whole production to a model; it is a small paid test, so it needs the usual authorization.

Next handoff: exact selected files/IDs in narration or speaker/line/chunk order, measured durations, beat spans, defects and next action to `audio-post-mix`. Generation is not approval. Use finalized narration edits for captions and cue placement.

## OpenRouter speech
Resolve route from the production choice, else `routes.openrouter` (`default` or exact model-id override). Read `studio` → `references/openrouter.md` for environment checks, live discovery, price approval and `spend.credits_per_usd`. Use the selected model's `supported_voices`; ElevenLabs account/library ids may not work here and the voice may differ from the direct ElevenLabs route. Explain that conflict to the user; never silently swap a kept voice. ElevenLabs music, SFX and voice-library access remain on the direct route.

After authorization, run in the production folder. This example uses `elevenlabs/eleven-v4` / `george`; use the resolved model and supported voice, with the full selected chunk in `render-text.txt`. JSON reads the text as data, preserving quotes and newlines:

```sh
jq -n --rawfile text render-text.txt --arg model 'elevenlabs/eleven-v4' --arg voice 'george' \
  '{model:$model,input:$text,voice:$voice,response_format:"mp3"}' > speech-request.json
curl --fail --silent --show-error https://openrouter.ai/api/v1/audio/speech \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" -H 'Content-Type: application/json' \
  --data-binary @speech-request.json --dump-header speech-headers.txt --output speech.mp3
```

The response is raw audio bytes (`audio/mpeg` or `audio/pcm`), not JSON; explicitly request `mp3` because the default is `pcm`. Check HTTP success before registering the file; errors are non-200 JSON. Record `X-Generation-Id` from the response headers and the actual model/voice/settings, chunk mapping and text hash. Persist the local file with `asset-persist`; keep the same listening gates and measured handoff above.

[verified] `instructions` is honored by OpenAI gpt-4o-mini-tts, Gemini TTS and Fish Audio; ignored elsewhere. For `elevenlabs/*`, omit it. [observed] instructions: accepted without error but had no observable effect on elevenlabs/eleven-v4 in one A/B (2026-10-17); do not rely on it; output is nondeterministic so one test is indicative, not proof

[verified] ElevenLabs bracket tag syntax is accepted in `input`, counting toward character limits and Unicode-code-point billing. [maintainer-observed] Delivery is model-specific; follow the shared tagging reference for listening review. [verified] v4/v4 Turbo have no speed control: omit `speed`; use tags/punctuation. OpenRouter documents speed 0.7-1.2 only for Multilingual v2 and Flash at `provider.options.elevenlabs.voice_settings.speed`. Put ElevenLabs-specific settings (seed, context, language/normalization, pronunciation dictionaries, supported voice settings, codec-matched output format) under `provider.options.elevenlabs`; exact keys/caveats are in the shared reference. Unlisted keys are ignored; invalid listed values return 400. The announcement, not the TTS docs page, documents these ElevenLabs keys.

Multi-speaker `input` turns work on Gemini TTS and Fish Audio non-S1; otherwise render mapped speaker chunks separately. Voice cloning/design uses provider-specific `input_references` (1-3 input_audio parts with optional text, at most 20 MiB base64 per part); verify the selected model's current shape and consent before use. `provider` supports `zdr`, `data_collection`, `options`. Do not forward ElevenLabs tags/settings to another model without checking support.
